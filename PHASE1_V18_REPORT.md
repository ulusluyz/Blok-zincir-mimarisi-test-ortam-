# V18 — Evidence probe multi-topic comparison

Independent comparison against `dynamic_multi_label` on the 10 held-out multi-topic examples in `src.dataset`. The experiment uses 128-bit learned encoder (seed 42, 15 epochs) and **static** G representatives derived from the first training example of each category; three A blocks per group. Thus this is **not** a reproduction of the previously reported 51.7% result from a different trained-G setup. Execute `PYTHONHASHSEED=0 OPENBLAS_NUM_THREADS=1 python compare_probe_v18.py` for reproducibility. The feature vocabulary's frequency ties can change when Python's hash seed is not fixed.

The detailed JSON file `PHASE1_V18_PROBE_COMPARISON.json` contains the exact measurements. In the controlled run, the baseline recalled 12/23 expected groups (52.17%). Probing five groups recalled 16/23 (69.57%), improving by 4 groups / 17.4 percentage points. Joint retrieval increased from 1/10 to 4/10 queries. Probe-5 evaluated 24 A similarity operations per query versus 5.4 in the baseline (4.44 times more). The increase in recall is promising but this small sample does not establish statistical significance. Timing measurements are noisy and should not be used to claim a speedup.

Important: V17's `total_a_evaluated` did not count A scores calculated during probing. V18 adds `probe_a_evaluations` and `total_a_score_operations` without changing routing selection behavior. It is inappropriate to call this sparse A evaluation at the same cost as baseline. Probe-10 had no recall gain over probe-5 in the controlled run while using more scoring operations. Do not enable evidence probing by default yet. Next validation should use repeated seeds, disjoint data, latency distributions, and a strict A-evaluation budget.

The full pytest suite was attempted but exceeded the execution time limit in this environment; focused routing and cost tests were run separately. Hardware power-loss tests remain open. GitHub not modified.
